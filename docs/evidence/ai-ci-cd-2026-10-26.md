## 1. AI tests and evaluation in CI

The `Backend - Python` job now runs, in order:

1. `pytest -m "not db"` with a dummy `DEEPSEEK_API_KEY`, and with `HTTPS_PROXY`/`HTTP_PROXY` pointing at an unreachable port. The suite includes the #57 evaluation suite (`test_week3_evaluation.py`: 12 success and 15 regression fixtures, with an exact match against the committed report), the mocked provider and extraction API tests, and the recommendation contract, content and hybrid tests.
2. `evaluate_week3.py`, which writes the fresh report.
3. `compare_evaluation.py`, which compares the report with the **target branch's** committed baseline. The table goes to the job summary, and any regression fails the job. It also names a changed prompt, configuration or fixture hash.
4. The report is uploaded as the `ai-evaluation` artifact.

Local check before pushing: with the proxy guard on, **305 tests passed**, and a direct `httpx.post("https://api.deepseek.com/chat/completions")` failed with `ConnectError`, so no real provider request can leave a CI job.

### Post-merge identity scoping

Run these after the first green environment-based production deploy:

```sh
P=relax-mode-lagaw
POOL=projects/663710289405/locations/global/workloadIdentityPools/github
# 1. Expose the environment claim on the production provider (tokens without it map to "none").
gcloud iam workload-identity-pools providers update-oidc github --project $P --location global \
  --workload-identity-pool github \
  --attribute-mapping='google.subject=assertion.sub,attribute.repository=assertion.repository,attribute.ref=assertion.ref,attribute.environment=has(assertion.environment) ? assertion.environment : "none"'
# 2. Bind each deployer to its own environment only.
gcloud iam service-accounts add-iam-policy-binding gh-deployer@$P.iam.gserviceaccount.com --project $P \
  --role roles/iam.workloadIdentityUser --member "principalSet://iam.googleapis.com/$POOL/attribute.environment/production"
gcloud iam service-accounts add-iam-policy-binding lagaw-api-staging-deployer@$P.iam.gserviceaccount.com --project $P \
  --role roles/iam.workloadIdentityUser --member "principalSet://iam.googleapis.com/$POOL/attribute.environment/staging"
# 3. After one green staging and one green production deploy, remove the repository-wide trust.
for sa in gh-deployer lagaw-api-staging-deployer; do
  gcloud iam service-accounts remove-iam-policy-binding $sa@$P.iam.gserviceaccount.com --project $P \
    --role roles/iam.workloadIdentityUser --member "principalSet://iam.googleapis.com/$POOL/attribute.repository/relax-mode/lagaw"
done
```

**Rollback.** If any deploy then fails to authenticate, re-add the binding removed in step 3.
