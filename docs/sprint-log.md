- **October 14, 2026** — Cloudflare Pages project `lagaw` created with Wrangler (`--production-branch main`; production URL `https://lagaw.pages.dev`) on Kyle's Cloudflare account. Wrangler 4.151 delegates new Pages projects to Workers and failed, so the project was created once with `--force` (classic Pages), as Wrangler's own error advised; later commands need no flag. Added `package.json` pinning `wrangler@4.151.0` and a first-draft deploy job (reworked in the next entry). Setting the repository secrets was initially blocked because the repository was a personal account repo where Kyle had push but not admin access; see the next entries.
- **October 14, 2026** — Deploy pipeline finalized. A first draft put the deploy in its own `deploy-web.yml`, which rebuilt the web app on `main` even though `ci.yml` had just built it. Replaced with a single `deploy-web` job in `.github/workflows/ci.yml` that reuses the `frontend` job's build artifact, so each run builds once. `main` deploys to production and same-repo pull requests deploy a preview (fork PRs skipped). The job deploys only when the frontend (excluding `frontend/test/`) or deploy config changed, so docs-only and test-only merges do not deploy, decided by changed files rather than branch names (a branch-name rule was dropped as fragile). It skips cleanly while there is no Flutter web project or the Cloudflare secrets are unset. Also fixed a bug in the draft where a failed `wrangler` deploy piped into `tee` would still report success (added `set -eo pipefail`). Tested the gate script locally across 12 scenarios (app, test-only, docs-only, config, mixed, PR ranges, zero/bad base commit, manual run, missing secrets, missing web platform) and ran the exact `wrangler pages deploy` command against a placeholder on the preview branch `deploy-check` (preview deployment `04d92b05` is a leftover test artifact). The full run on GitHub is untested until the change is merged, `frontend/` exists, and the secrets are set. Not yet adopted: see [CI/CD best practices](cicd-best-practices.md).

- **October 15, 2026** — Backend hosting decision recorded: the FastAPI backend moves from the open "Render or Railway" option to Google Cloud Run, replacing it. Reasons: scale-to-zero with no idle sleep penalty on a stable URL, tight cost controls (`max-instances=2`, small budget), and keyless deploys from GitHub. Kyle created the Google Cloud project `relax-mode-lagaw` under his organization, linked the account's only open billing account, set a $3 monthly budget alert on the project (alerts only; it does not cap spend), and enabled the Cloud Run, Artifact Registry, Secret Manager, IAM, and Cloud Build APIs. Region `asia-southeast1` (Singapore) was chosen for latency to Bacolod; it uses higher regional pricing than US regions. Artifact Registry repo `lagaw` keeps the 5 newest images. GitHub Actions deploys through Workload Identity Federation limited to `relax-mode/lagaw` on `main`, with service accounts `gh-deployer` (deploys) and `lagaw-api` (runtime, read access to its two secrets only). Supabase `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY` were loaded from Kyle's local gitignored `.env.local` into Secret Manager through the shell; values never appear in the repository, this log, or command output. The backend gained a `Dockerfile` and `.github/workflows/deploy-backend.yml`. CORS itself came from the developer's separately merged pull request #19 (exact origins in `CORS_ALLOWED_ORIGINS`, no wildcards); an earlier wildcard-style draft of mine was dropped in favor of it, and the deploy sets `CORS_ALLOWED_ORIGINS=https://lagaw.pages.dev` on the service from a GitHub Actions variable. Cloudflare preview URLs therefore cannot read the API unless explicitly added. Validated by hand before merging: the image built in Cloud Build, a private Cloud Run service returned live rows from the production database, CORS (my draft, before adopting #19's) allowed `https://lagaw.pages.dev` and rejected other origins, and unauthenticated requests got 403. Cloud Build needed an explicit build service account with logging, storage-read, and registry-write roles (new-project default). The service was then opened to the public (`allUsers` as `roles/run.invoker`), which the browser app requires.
