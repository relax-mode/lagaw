## Summary

Lagaw is a travel-planning app for Bacolod. It has a Flutter client (Android and Web), a FastAPI backend on Google Cloud Run, a Supabase PostgreSQL database, and Cloudflare Pages hosting for the web build. Users sign in, create and edit trips, get recommendations for a trip, and generate a trip itinerary. Structured preference extraction from free text is provided by a DeepSeek-backed endpoint with a manual fallback when the provider is unavailable.

The full list of changes is in [CHANGELOG.md](../../CHANGELOG.md).

## Known limitations

These are stated as they stand in the repository and open issues. Each one must be re-checked before the release is approved.

- **Authentication email delivery is limited.** Supabase Auth email uses its default provider until custom SMTP is configured. Default limits apply to sign-up confirmation and password recovery emails, and the owner must confirm the current limit. Tracked in #113 (open). Background: #97 and #112.
- **Onboarding and personalized discovery are not finished.** The onboarding flow, its preference API and cold-start discovery are open (#101-#104). Discovery swipes and saves are not yet wired to the Flutter UI (#110).
- **Destination data is incomplete.** Opening hours, cost and visit duration are not verified for every destination, and the catalogue is not yet enriched for feasible itineraries (#105, #106). Destination images are not integrated (#107-#109).
- **Android release build and some UI states are not verified.** Release-mode identity and misleading loading, empty and error states are open (#117).
- **AI endpoint rate limits and cost safeguards are not in place.** Per-user limits and daily quotas are open (#114). Failure handling documentation is open (#115).
- **Scheduled AI smoke checks and production verification are open.** The authenticated scheduled check is tracked in #118.
- **The collaborative model serving issue (#94) is still open**, although its pull request (#95) is merged.
- **Backend health and API documentation are open.** No dedicated health or version endpoint exists yet (#116).
- **Rollback drill is open.** The rollback runbook and a tested staging rollback are tracked in #120.
- **Sprint 3 consultation evidence is open** (#59, #122).
